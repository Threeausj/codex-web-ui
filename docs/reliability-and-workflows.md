# 登录、缓存与桌面工作流改进

## 登录与通知

通知初始化、订阅恢复和 HTTP 请求有超时，挂起后可重新初始化。测试通知落盘入队即返回 202，投递结果通过状态接口查看；本地退避上限不截短服务端 Retry-After。正常投递队列最多 1,024 条，另有四倍容量的持久积压；再次溢出计入设备失败及容量丢弃数，设置中可见。

网页登录授权以 bearer ID 的 SHA-256 保存到私有 `DATA_DIR/web-sessions.json`，不保存网页登录密码或原始 Cookie。记录包含 CSRF、到期时间、凭证代数与 HMAC 签名，以 0600 权限原子替换。服务重启后已有授权继续有效；退出、改密码、过期及签名校验失败仍会撤销授权。首次从旧版内存会话升级需重新登录一次，之后的正常重启不要求重复登录。`DATA_DIR` 必须持久挂载。

注销以后端撤销为准；浏览器推送 unsubscribe 失败不会阻止注销。显式注销的推送授权撤销另有持久记录，即使推送订阅文件写入失败也不会恢复通知授权。

通知按设备记录待投递状态。网络错误、超时、429 或推送服务 5xx 使用有界退避重试；最多八次、保留一小时，尊重 Retry-After，队列在重启后继续处理。410/404 等失效订阅停止投递。相同任务事件按设备去重，通知使用稳定 tag/topic；无法保证厂商或手机一定送达。子智能体与临时侧边聊天不触发整个任务完成通知，无法确认来源的完成事件先核实再发送。设置内可查看本设备排队数及最近投递结果，不暴露订阅地址、私钥或通知正文。

## 历史、连接与渲染

超过 80 个历史块时，正文按可见范围挂载并保留占位高度；当前运行轮、编辑与选区保持挂载，手动展开状态保留。分组采用线性遍历，已解析的 Markdown 段落使用有界内存缓存。编辑器、PDF 和语言支持首次使用时加载，Service Worker 只缓存构建清单中的公开资源。

内存缓存使用 LRU 管理当前／后台会话，保护当前及运行中任务；普通预算为 24 个会话／12 MiB。已完成任务会重新计量，受保护任务可以暂时超出预算。IndexedDB 的私有会话快照仍为 12 个／4 MiB、24 小时、单条 768 KiB；超限保留裁剪后的最近内容，并标记为缓存预览，不删除整条快照。缓存仅用于先展示，不能恢复或授予原生写入资格。

重新选择会话先核对 writer 与最新 30 轮。已验证同一引擎、连续事件且最新页含已缓存末轮时，复用已加载历史与分页游标；360 轮历史不再被 300 轮上限覆盖，也不再重复串行读取十二页。回退、归档或缺口会失效旧范围，先核对最新状态，再补读历史。后台消息合并缓存失效事务，历史项目使用 ID/clientId 索引合并。引擎升级会重新探测模式与技能，临时失败不永久缓存为“不支持”。

服务端缓存最多 4,096 条／4 MiB／五分钟的事件。短暂断线后按相同 engineId 与序号补发，超过窗口或更换引擎仍核对原生历史；不重发命令、消息或队列操作。私有 RPC 结果不进入重放缓存，已解决审批使用序号占位避免再次显示。操作结果先返回发起者，再确认事件序号，防止收到 ACK 却漏掉接受结果。健康连接的导航兜底刷新降为 60 秒，断开状态为 15 秒。

工作过程、操作批次、单项工具及单文件 diff 逐层按需挂载。收起后不创建命令输出或万行 diff 的 DOM；实时助手 Markdown 按动画帧合并更新。本地 Markdown 图片使用来源主机的鉴权接口，相对路径在该对话工作区内解析，图片可点击打开文件。远程图片仍按原有 Markdown 行为显示。

## 文件保存与变更范围

多文件标签和草稿按有效登录、主机、项目保存到独立 IndexedDB，包含原始文本和保存版本。重连只刷新目录；关闭工作区、换标签或刷新保留草稿，显式关闭脏标签需要确认。最多 16 个标签，私人工作存储最多 256 条／64 MiB，超限明确提示，不淘汰未保存内容。退出登录清理；存储不可用时只保留当前页面内容。详见[文件工作流](automations-and-editor.md)。

打开文件时由同一次原生读取计算版本 SHA-256；保存前服务端再次核对，并串行处理同主机／规范化路径的 Web 保存。409 冲突保留草稿并展示磁盘版本；可重新载入，或显式以新磁盘版本为基准手动合并。合并后的再次保存仍核对版本，文件上限八 MiB。

公开 Codex `fs/writeFile` 没有 expectedVersion/CAS 参数。这能检测保存前已存在的外部改动，并阻止两个 Web 保存同一旧版本，但**不能锁住不配合的 CLI／桌面写入者**，最终核对与写入之间仍有原生协议窗口；不同符号链接路径也不等于同一锁。手工文件读写使用部署／SSH 用户的系统权限；Codex 对话沙箱不是整个管理网页的系统 ACL。只读模式的编辑器保存入口继续禁用。

变更面板保留每次补丁，提供“已加载操作记录／上一轮操作”。行数明确为累计操作，重复修改或撤销不伪装成净变化；工作区净差异与暂存差异在 Git 查看。未加载历史不会标为整个对话的全部修改。

## 排队、审阅与工作树

添加和手动启动队列前，先确认 thread/settings/update 保存了下一轮模型、强度与权限，当前运行轮保留启动设置。队列有消息时锁定相关控件，清空后可改；原生队列没有逐条权限或暂停字段，其他原生客户端改变线程设置仍会影响下一轮。提交前持久保存原操作 ID，刷新后核对未知回执；相关私人存储不可用时阻止提交。

保存侧边分支时关闭面板只隐藏视图，已发送操作继续处理。正式分支 ID 和追加阶段保存在私人回执中；刷新后继续核对相同分支，创建或追加结果未知时禁止重复提交。退出登录清理私人回执。

运行中输入框可选择“立即补充／下一轮排队”，默认立即补充。排队使用原生 thread/queue API，可查看、编辑、移除、重排，并在空闲时显式启动；多端事件刷新队列。队列消息保留附件、技能与引用。未知提交结果先核对，不盲目重试；旧 CLI 或无法确认能力时禁用。任务结束后恢复普通发送，防止新设置未同步时继续沿用旧排队设置。队列由当前原生进程托管，关闭浏览器不丢失；这不等于独立于 Web 服务的任务 daemon。

`/review` 提供未提交修改、基准分支、指定 commit 与自定义范围，直接调用原生审阅，不合成用户聊天提示。审阅前以 thread/settings/update 应用当前模型、权限、审批与推理强度；无法确认旧 CLI 支持时不沿用错误权限。结构化 findings 可打开文件并定位行。

Git 工作树可指定起始分支并创建新分支，准备独立新会话的目录。首次发送时原生 thread.cwd 记录绑定；空白欢迎界面不宣称已经有持久对话。清理仅使用非 force 的 worktree remove，拒绝主仓库、当前工作区、运行中 Web 会话、锁定工作树、未提交或 ignored 文件，不删除分支或会话历史。Linux 还核对当前 CODEX_HOME 的真实 writer flock，并只读查询 CLI／桌面会话目录；无法确认时阻止清理，不删除锁或结束外部进程。其他 CODEX_HOME 与检查后新启动的写入者仍需使用者协调。

侧边问答可沿用首次历史锚点、另开分支、引用回答，或把新增可见问答保存到正式分支。创建结果未知时阻止重复创建；已知分支内的后续失败可以恢复，新增问答只增量追加。原生未发送过新轮次的 fork 可能不出现在 thread/list；保存会明确置顶该分支，重进时按 ID 重新读取。注入记录是模型参考上下文，原生聊天时间线仍遵循公开协议的历史显示方式，不伪装成完整原生问答／工具重放。详见 [侧边提问](selection-side-chat.md)。

## 能力与诊断

设置支持技能启停、显式 MCP OAuth 登录、状态刷新与配置重载；动作按实际 CLI 的协议字段门控，并处理引擎变化与过时响应。能力读取在临时独立 CODEX_HOME 中生成公开 schema，不启动模型，不读取用户配置到浏览器；版本或连接模式无法确认时保持未知。

主机诊断展示 CLI、引擎、连接／重连、最近协议错误分类和事件窗口，不启动或重启主机。模型服务层级同时由原生协议与该模型 serviceTiers 决定；没有目录声明时不猜 Fast 或网关支持。额度来自后端窗口和重置时间，ordinaryUsageAllowed 的限制状态单独显示，不凭百分比推断账户授权。

定时任务由 Web 服务端调度，保留执行记录并处理执行前重试、未知回执与重启后的结果核对，见[自动化说明](automations-and-editor.md)。它不保证默认 spawn 模式的活动推理跨 Web 重启继续运行。桌面系统窗口／全局热键、完整 GitHub PR 管理和逐 hunk 写入仍待实现。
