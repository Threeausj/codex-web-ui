# 项目审查与改进建议（2026-10-08）

本轮审查覆盖前端会话与缓存、草稿和文件编辑、后端鉴权及 WebSocket 桥接、SSH/文件/Git 边界、自动化持久化、PWA、Docker 与文档。结论基于当前代码、完整测试及可复现的失败注入，不代表已验证所有真实手机或远端环境。

## 本轮修复

| 问题 | 原因与影响 | 修改与验证 |
| --- | --- | --- |
| 开发依赖的已知命令注入漏洞 | `concurrently` 固定引用受影响的 `shell-quote@1.9.0`，普通 update 不会更新它。它属于开发工具依赖，未确认生产请求能触发漏洞 | 定向 override 到修复版本范围，锁文件安装 `1.12.0`；开发启动器的两个子命令验证通过，完整依赖审计未检出漏洞。见 [GHSA-pqg4-j6r4-53mv](https://github.com/advisories/GHSA-pqg4-j6r4-53mv) |
| 删除主机与项目保存竞争 | 两个独立写入队列都修改项目集合；删除主机时可能覆盖另一主机的新项目，并可能保存已删除主机的项目 | 主机与项目共用串行队列；入队后重新验证主机；启动时过滤孤立记录。失败时恢复项目元数据；阻塞重命名和磁盘失败测试覆盖内存、重启与队列继续使用 |
| 私有 JSON 写入失败留下临时文件 | 写入后 rename 失败缺少清理，可能留下包含私有配置的临时文件 | 独占创建 `0600` 临时文件，写入并同步后替换，成功／失败均清理；失败验证旧文件不变、无临时文件残留 |
| 自动化配置与运行日志互相覆盖 | 写入排队前已生成旧快照；失败回滚使用旧任务数组，可能丢失另一条成功保存的配置 | 配置和调度入队串行化；配置落盘后才发布到内存；日志快照在执行写入时生成；失败保存与同时到达的完成事件都有回归覆盖 |
| 浏览器发送失败影响共享连接 | 客户端发送异常可能被当作原生协议异常，断开整个 app-server；慢客户端也没有发送积压上限 | 浏览器错误、同步 send 异常及回调失败只终止该浏览器连接。随后用大对话复现发现原 8 MiB 发送积压阈值会误断大历史；现使用有序发送和额外等待队列限制，详见 [大对话与多端同步](large-conversation-sync.md) |
| 存储满／禁用时草稿与启动异常 | 草稿、客户端 ID 和部分偏好直接读写 Web Storage，异常可能打断界面，或把新草稿替换成旧保存内容 | 读取／写入失败不抛出到应用；失败值在当前窗口保留，显示关闭前复制提醒；恢复存储后正常持久保存。浏览器验证切换对话、发送成功后的清空，以及完全禁用存储后登录和发送 |
| 旧对话的模型选择空白 | 恢复会话使用了提供方未列出或隐藏的模型，select 没有对应选项 | 保留并显示会话当前模型，不自动替换；用户仍可明确切换到列表中的模型；验证发送时保留原模型 |

## 后续建议与优先级

| 优先级 | 改进 | 理由与验收方式 |
| --- | --- | --- |
| 高 | 将聊天草稿迁入按登录作用域管理的私有 IndexedDB，统一草稿清理和容量策略 | 文件草稿已有私有状态服务，聊天草稿仍使用独立 localStorage 键。迁移时保留旧数据、避免延迟读取覆盖新输入；验证多窗口、退出、密码轮换、存储满和页面回收 |
| 高 | 主机／项目元数据使用统一事务或恢复日志 | 本轮处理正常并发与可捕获的 IO 失败；两个独立 JSON 文件在进程突然停止或断电时仍没有跨文件原子性。模拟每个写入阶段突然退出，重启后保证已确认的配置可恢复 |
| 中 | 拆分 `useCodex.ts`，逐步替换 `any` 与重复的协议适配 | 单文件承载连接、历史、目标、队列、文件与权限等功能，修改时容易牵连状态恢复。按连接生命周期、历史仓库、工作站能力和会话命令拆分；先保留现有行为和错误语义，再逐步补严格类型 |
| 中 | 对开发预览 WebSocket 也增加积压限制与独立故障处理 | 主聊天桥接已处理慢客户端；预览代理拥有另一套 WS 转发。使用真实 Vite HMR／大输出和慢浏览器验证，避免误断正常预览 |
| 中 | 增加可重复的性能基准 | 现有测试验证缓存立即展示、历史增量补齐和懒加载；还应记录冷启动、缓存切换、长会话、SSH 延迟下的耗时与内存，观察 P50/P95 和发送积压，而非仅依赖体感 |
| 中 | 按需加载设置／资源／自动化等面板 | 本轮生产主入口约 627 kB，gzip 约 207 kB；源码编辑器与 PDF 已独立分块。继续拆分时需同时验证首次打开的加载提示、焦点、取消及 PWA 离线资源，不能只调整构建警告阈值 |
| 中 | 有条件启用仓库 CI，并增加故障注入检查 | 仓库已有可选 GitHub Actions 模板，尚未启用。CI 应执行锁文件安装、类型、单元、浏览器、Docker 非 root 集成和依赖审计，避免文档计数代替可重复验证 |
| 环境验收 | Android PWA 锁屏推送、软键盘、原生返回及长时间后台恢复 | Chromium 页面冻结／回收测试不等于真实 Android 系统验收。纯 PWA 无法强制系统把返回手势转成原生挂起；仍需在目标设备测试系统省电、权限和安装启动方式 |

原生 `fs/writeFile` 没有条件版本写入能力，文件保存已做版本核对，但外部程序仍可能在最后核对与写入之间改动文件。这是已记录的协议边界；不要将当前保存保护描述成跨进程原子 CAS。详见 [可靠性与工作流](reliability-and-workflows.md)。

权限仍遵守用户选择与原生受管规则。自动化、Git 写入、终端和模型命令不会为避开 `bwrap` 自动扩大权限；主机指纹变化也不会自动忽略。
