# 对话引用、收藏与侧边提问

选择对话正文中的文字后，菜单提供“添加到对话”“在侧边聊天中提问”和“收藏”。支持桌面鼠标、键盘选择和手机长按；选择必须位于同一条消息正文，工具输出、输入框与按钮不会触发此菜单。单段最多 16,000 字符。

“添加到对话”将所选文字保存为输入框上方的引用，不覆盖现有草稿、图片或技能。每个会话最多八段引用，总计最多 32,000 字符，可以逐段移除。发送时引用作为独立的文本上下文附在问题后面；引用中的技能或应用名称不会自动触发调用，也不会成为 Goal 目标。发送失败会保留引用；接受后只移除本次发送的引用。引用跟随本地会话草稿恢复。

“收藏”首次打开名称编辑框，默认取所选文字的首行，可修改后保存或取消；名称最多 160 字符，保存失败保留输入。收藏名称独立于会话标题，不覆盖输入框草稿，也不发送消息或调用模型。

项目行的 `… → 收藏对话` 列出该主机、该项目的收藏，可按名称、摘录或来源会话名称搜索，并重命名、取消收藏。不同主机即使有相同项目路径或会话 ID，收藏也分别展示。取消收藏仅移除保存的位置和摘录，保留原会话。

点击收藏会切换到对应会话，定位并高亮原消息。较早的消息按原生轮次和消息 ID 分页读取，无须依次载入中间所有轮次。若原消息因回退或删除而失效，收藏和摘录仍保留，面板提示无法定位；若消息还在但文字已变化，则定位到该消息并提示变化。

收藏保存在 Web 服务端的私人文件 `DATA_DIR/bookmarks.json`，包含名称、摘录及来源位置。Docker 的 `webdata` 卷覆盖该文件，正常更新或重启后保留；不写入桌面 Codex 配置或对话历史。请将该文件与其他私人网页数据一并保留在持久化卷中。

右上角“新建侧边聊天”直接基于当前对话提问，无需先选中文字。第一次发送时才调用原生 `thread/fork`，使用 `ephemeral: true`、`excludeTurns: true`，不传历史截断边界，继承当时完整可用的上下文。主对话正在运行时仍可打开，原生分支会为未完成的轮次记录中断标记，主对话继续运行。已有侧边任务时，此按钮重新打开原分支；需要重新继承当前上下文时，使用面板中的“另开侧边分支”。运行中的父轮次产生的临时上下文无法从之后改变的持久历史准确重建，因此此类侧边问答通过“引用回答到主对话”保留，不提供可能丢失上下文的正式分支保存。官方说明见 [侧边聊天命令](https://learn.chatgpt.com/docs/developer-commands#start-a-side-chat-with-side) 与 [App Server 的 thread/fork](https://learn.chatgpt.com/docs/app-server#fork-a-thread)。

“在侧边聊天中提问”先打开问题输入框，不自动发送。发送时，网页通过 `thread/fork` 创建独立的 `ephemeral` 分支，再对该分支调用 `turn/start`，使用所选模型、推理强度与只读权限。已完成的轮次可以作为分支边界；从运行中的轮次选择文字时，分支仅继承它之前的历史，并额外传入所选文字。原对话的运行、权限、输入和目标均保持不变。关闭侧边聊天只停止、释放它自己的分支；切换工作区时可以暂时隐藏，再从顶部“新建侧边聊天”按钮重新打开，已有任务和未发送的问题会保留。

临时侧边聊天不加入普通会话列表，完成和失败不发送整个任务完成通知；需要用户处理的审批仍可提醒。主机管理策略可能限制只读权限或要求审批。旧版 Codex 如果不支持临时分支，会显示更新提示，不改成空上下文或操作原对话。

临时会话不持久保存，刷新网页或原生 Codex 进程重启后需要重新发起。当前实测 `codex-cli 0.160.1` 的临时会话不支持 Goal、历史分页和 `thread/read.includeTurns`；断线重连保留已经显示的内容，检查分支的只读状态，并提醒可能缺少断线期间的内容。不会自动重发问题或恢复原对话的写入者。

官方依据：[Developer commands](https://learn.chatgpt.com/docs/developer-commands) 记录了 `chatgpt.addToThread`；[官方更新日志](https://learn.chatgpt.com/docs/changelog) 记录了从选中对话文字发起侧边聊天；[Codex App Server](https://learn.chatgpt.com/docs/app-server) 公开了文本输入、分支和临时分支协议。网页交互由本项目实现，并不调用桌面应用专用按钮接口。


侧边面板现在显示首次继承的历史锚点。更换引用后，后续提问默认沿用该分支；“另开侧边分支”会先确认并关闭旧临时问答，再按当前选段继承历史。“引用回答到主对话”仅添加引用，保留主输入草稿，不自动发送。

“保存并置顶正式分支”不直接转换临时线程：实测 CLI 0.160.1 的临时线程没有可 fork 的 rollout。程序按首次记录的持久历史锚点 fork 独立正式线程，以只读权限、deferGoalContinuation 创建并清除新线程继承的 Goal，追加**可见用户／助手问答**为参考上下文，命名后释放 Web 写入者。隐藏推理、工具执行状态和断线遗漏内容不伪造。保存不调用模型，也不更改原对话；失败会显示已创建的分支 ID，避免再次创建。

正式分支保存后置顶；原生 `thread/list` 可能在首次新消息前省略尚未启动的新 fork，置顶记录会在重载时按 ID 补读。后续问答增量保存到同一分支。创建 ACK 未知时禁止重复创建，已知目标的追加未知时仅以原生落盘记录确认，不以“未找到”授权盲目重试。

创建 ACK 未知时可填写核对过的正式分支 ID。程序确认 `forkedFromId` 后直接清除继承 Goal 并设为只读，不 resume、不自动启动模型。

对话中的图片点击后在对话上方放大查看，支持缩放、原始尺寸、适应窗口，以及关闭按钮、Esc 和手机返回。上传图片、Markdown 图片及生成图片使用同一查看器；普通文件链接继续打开工作区。
