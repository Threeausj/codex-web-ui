# 独立 Codex 后台服务与连接恢复

SSH 主机可以让 Codex 作为独立 daemon 运行，网页服务通过 `codex app-server proxy` 连接它。这样更新或重启 Web 服务时，远端 Codex 进程与已经接受的模型任务可以继续运行；Web 恢复后重新连接并同步原生状态。协议与客户端连接方式见 [Codex 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

这项能力不把 Web 服务变成任务执行器，也不改变主机上的模型账户、配置与权限。任务实际运行在所选主机、执行账户及其 Codex 数据目录中。

## 选择运行方式

在 **设置 → 连接 → 添加或编辑 SSH 主机 → 高级选项 → Codex 运行方式** 中选择：

| 选项 | 连接行为 | Web 服务重启时 |
| --- | --- | --- |
| 独立后台服务（推荐） | 幂等启动目标账户的 Codex daemon，再建立本客户端的 proxy 连接 | daemon 与已接受的原生任务可以继续，Web 恢复后重新订阅活动会话 |
| 随网页服务启动 | 为该主机启动 Web 管理的 `codex app-server --listen stdio://` 子进程 | 子进程与其中的任务可能随 Web 服务结束 |
| 连接已有后台服务 | 只连接已经运行的 daemon，不负责启动、升级或重启它 | 只重建本客户端连接，已有 daemon 的生命周期由宿主管理 |
| 继承服务设置 | 沿用部署时的 `CODEX_CONNECTION_MODE`，未配置时使用 `spawn` | 取决于继承的运行方式 |

普通模式的结构化提问使用 Web 会话私有配置，保留显式会话选择；不会修改共享 daemon 的全局配置。已经加载的原生会话仍保留其运行配置。

新添加的 SSH 主机默认选择独立后台服务。已有主机保留原选择；未保存运行方式的旧主机继续继承部署设置，不自动迁移。切换运行方式会更换连接运行时，因此需要先等待该主机的对话、审批、终端与维护工作结束。

独立后台服务要求目标 CLI 支持原生 daemon 和 proxy 命令。首次连接使用该主机原有的 SSH 用户、Codex 路径和数据目录；连接测试不会运行模型。若 socket 或运行环境冲突，页面显示失败原因，不会查找并终止任意进程或删除 socket 来强制接管。

若目标 socket 上已有桌面端或 TUI 启动的兼容 App Server，原生 daemon 命令可能直接复用它。这类已有服务的生命周期仍由外部管理，网页可以连接与同步，但会禁用 daemon 重启、CLI 更新以及配置与账户修改。它不会因为选择“独立后台服务”就自动变成 Web 可管理的 daemon；需要在原客户端处理，或先核对空闲状态后另行迁移。

## 重连与更新分别处理

普通连接使用幂等的 `codex app-server daemon start`，已有 daemon 不会因网页连接、切换聊天或重新连接而自动升级或重启。

**设置 → 性能 → 重新连接 Codex** 在独立后台服务模式下只重建本客户端传输。已有模型任务或待回答审批不要求先停止；仍在执行的独立 Web 终端、未结束的 RPC 或正在进行的维护操作会阻止重连。恢复后重新读取版本、模型与配置；安装了新 CLI 并不意味着 daemon 已经运行新版本。

若只需让托管 daemon 重新加载静态模型目录或启动配置，可使用同页的 **重启 daemon**。按钮以服务端空闲状态为准，点击后需确认；执行 `codex app-server daemon restart` 前还会检查任务、审批、终端、排队消息和自动化。这个操作也会使连接同一 daemon 的其他客户端重新连接。外部管理的已有服务禁用此操作。

对于已经由原生 daemon 管理的服务，需要采用新安装版本时，使用 **更新并重启 Codex**。它先检查运行中的任务、审批、终端、待执行消息及自动化，取得维护锁，再依次：

1. 在目标主机执行 `codex update` 并读取安装版本。
2. 在同一账户及 Codex 数据目录中执行 `codex app-server daemon update --from-cli --yes`。
3. 重新连接并核对实际运行版本，刷新模型与配置信息。

更新需要主机空闲，不强制停止正在运行的任务。切换模型提供方等需要重启运行时的显式设置操作也会先检查空闲。外部管理的“连接已有后台服务”仍需由宿主更新；普通重连不会代替 daemon 升级。

## 会话如何恢复

Web 使用原生会话与事件同步恢复连接，不重新发送用户消息或自动补发一次模型请求。恢复时只尝试加入本服务已知、仍被 daemon 加载且处于活动状态的会话；不会扫描磁盘恢复所有历史会话，也不会为此启动一个已经空闲的 Goal。

`DATA_DIR/daemon-sessions.json` 保存有数量、体积和有效期限制的恢复提示，包含主机标识、主机连接身份的散列、thread id 与记录时间。它不保存消息正文、文件内容、密钥或审批答案。主机连接身份变化后不复用旧提示，原生 daemon 仍是会话状态的来源。

重连后，审批和工具提问由原生会话重新下发；网页不会从旧请求缓存重放答复。daemon 已退出、主机断网、恢复读取失败或原生协议能力不足时，页面仍可能需要手动同步或重新打开会话。若一次发送在断连时未收到确认，应先同步核对是否已经接受，再决定是否重试。

Web 的通知、自动化和资源采集仍由 Web 服务负责。Web 停止期间这些功能不能及时投递或调度；任务继续运行不代表停机期间所有事件与通知都能完整补发。恢复状态以 daemon 返回的实际结果为准。

## 暂停、删除与终端

- 在资源管理中暂停主机后，Web 保留暂停状态，不在重启或后台恢复时自动连接；使用“连接 Web Codex”显式恢复。
- 独立后台服务或外部代理模式下，删除 SSH 主机只关闭本客户端的 proxy 连接及订阅，不执行 `codex app-server daemon stop`。远端进程和数据仍由该主机账户管理。
- 聊天中的停止、归档或删除仍可能终止会话任务。独立 daemon 模式不提供资源面板的单会话“关闭会话”功能，避免通过归档方式释放共享 writer；需要停止时使用聊天内的停止按钮。

普通工作区终端通过原生 `command/exec` / PTY 连接运行，关闭终端或重建客户端连接可能使它结束；不能保证它在 Web 服务重启后存活。长时间训练、开发服务器或其他需要独立保留的命令应运行在目标主机的 tmux 会话内，之后重新连接 tmux 查看输出。tmux 进程本身也需要所在主机或容器持续运行。

独立 daemon 提供的是 Codex 运行时与网页服务的生命周期分离。它不能保证目标主机重启、daemon 自身更新或进程崩溃时任务继续运行，也不提供跨主机的云同步。
