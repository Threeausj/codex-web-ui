# Tmux 任务监控与 GPU 进程

“资源管理 → Tmux 任务监控”集中查看所有主机的监控与执行记录。选择目标主机，点击“发现窗格”，添加一次或持续监控；工作区的 Tmux 输出窗口也可直接监控当前窗格。

- **本次任务**：若窗格正在运行程序，跟踪当前前台任务；若当前是空闲 Shell，则等待下一次任务。任务结束后此监控完成，不再继续通知。
- **持续监控**：每次前台任务结束后继续等待下一次。使用会话名称、窗口序号和窗格序号确定逻辑位置；该位置重新创建后可以继续跟踪，因此只应对自己需要持续监控的位置启用。
- **停止与删除**：只暂停或删除 Web 的监控记录，不发送按键，不停止 tmux 会话或远端训练。删除监控仍保留已有执行记录。
- **后台执行**：监控由 Web 服务采样，关闭浏览器后继续，不依赖页面订阅或 Codex 模型运行。Web 服务停止期间无法采样；重启后恢复监控，依据当前状态核对任务。SSH 断连或读失败显示“等待重连”，不会直接误报任务结束。
- **通知**：沿用“设置 → 应用与通知”的设备授权、通知偏好与持久投递队列。事件先落盘，再用固定事件 ID 投递，避免重启或重复采样造成重复通知。执行记录“已提交通知队列”只说明服务端已受理；手机系统是否展示仍受系统网络及推送服务影响。

默认约每 5 秒采样，短于采样间隔的任务可能无法发现。监控读取前台进程组，管道中当前命令名称变化不等于任务完成。普通交互 Shell 返回提示符时无法可靠读取上一条命令的退出码；此时记录“任务已返回 Shell”，不声称成功。tmux 保留已退出窗格且提供退出状态时，才能准确区分正常退出与非零异常退出。实现不会安装 tmux hook，也不会修改 `remain-on-exit`。

监控与执行历史保存在私有 `DATA_DIR/tmux-monitors.json`，应随持久数据卷备份。最多 64 个监控，保留最近 300 个已提交通知队列的历史记录和仍待投递的记录；清除执行记录不会丢掉待投递事件。

资源管理的“GPU 进程”表补充了整卡统计之外的进程信息：GPU、用户、PID、显存、运行时间及命令。需要 NVIDIA 驱动的计算进程查询支持；容器 PID 命名空间或 `/proc` 权限会使部分字段显示未知，其他显卡数据仍保留。最多显示 128 个计算进程，命令只显示有长度上限的预览。
