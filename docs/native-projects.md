# 原生项目归属与桌面分类

工作目录与项目归属是两个不同字段。`cwd` / `runtimeWorkspaceRoots` 决定 Codex 可以在哪些目录工作；支持原生项目的客户端通过 `projectId` 判断会话属于哪个项目。Web 自有的 `web-*` 项目 ID 不能直接作为原生项目 ID。

Web 首次发送消息、创建审阅／工作树源会话及执行自动化时，会为当前已保存的 Web 项目解析原生身份：

1. 在目标主机调用 `project/list`，读取所有分页。
2. 对目录进行规范化，按完整根目录集合匹配已有项目；同目录存在多个项目时，只有名称唯一匹配才复用，否则提示歧义并保留草稿。
3. 没有匹配项目时，通过 `project/create` 创建，使用稳定的幂等键。并发请求共享在途操作；后续请求重新核对原生项目，避免桌面修改后使用过期记录。
4. `thread/start` 同时传入工作目录和原生 `projectId`。已有会话继续使用原有身份；不会按目录批量重新归类历史会话。

项目查询失败、超时或返回不兼容格式时停止创建会话，保留消息和附件。只有明确不支持项目方法的旧 Codex 才继续使用目录模式。自动化在创建会话前完成项目解析，因此查询失败可以按照既有连接重试策略恢复，不会重复提交模型任务。

## 手动移动对话

在侧栏会话的 `… → 移动到项目` 中选择同一主机的目标项目。Web 解析目标项目的原生 ID，再通过 `thread/metadata/update` 保存归属；会话随后出现在目标项目下，其他已连接网页同步更新。

移动只调整项目分类，保留消息、草稿和会话原有工作目录，不移动磁盘文件。需要在新目录执行任务时，应在该项目创建新会话。目标主机的 Codex 必须支持原生项目接口；不支持时会显示错误并保留原归属。

## 兼容边界

这些接口和字段已对照 `codex-cli 0.160.1` 与 `0.163.0` 生成的实验协议核对，Bridge 已启用 `experimentalApi`；使用其他版本时以目标主机的实际支持情况为准。类型定义见 `shared/protocol/v2/ProjectCreateParams.ts`、`ThreadStartParams.ts` 和 `ThreadMetadataUpdateParams.ts`。

部分桌面版本仍将项目和手动移动的会话归类保存在桌面客户端的本地状态中。此时，远程主机 `project/list` 可能为空，即使桌面侧栏已经有项目；旧会话的 `projectId` 也可能为空。Web 无法通过远程主机的接口写入这套客户端本地分类。原生身份补全不会保证这些桌面版本自动将会话加入已有的同名项目，也不会修改其私有 `.codex-global-state.json`。

如果 Web 会话出现在桌面“聊天”中，先确认目标主机和工作目录，再在桌面将该会话移入正确项目。支持原生项目的客户端可以直接读取原生归属；旧桌面分类需要在桌面端处理。会话出现在“聊天”不表示历史或工作目录丢失。

官方 [Projects and chats](https://learn.chatgpt.com/docs/projects?surface=app) 介绍项目、工作目录与远程项目的区别；[App Server](https://learn.chatgpt.com/docs/app-server) 介绍协议和实验 API。项目接口的具体字段以当前 CLI 生成的 schema 为准，公开指南不一定同步覆盖最新实验字段。
