# 后台通知观察与恢复

任务通知包含两个独立环节：Web 服务观察到 Codex 完成／提问／失败事件，再把通知持久写入设备投递队列并发送给推送服务。推送服务已接受，不等于手机系统已经展示。设置中的“检查系统通知”只在当前设备本地显示；“发送测试通知”才经过服务端和手机推送服务。

本轮修复了“电脑打开 PWA 后手机才收到”的服务端触发缺口：此前仅在服务启动时尝试连接一次，首次启用通知和 SSH／app-server 断线都缺少独立的后台维护。现在有效设备授权会启动后台观察，按主机自动重连和退避；所有浏览器关闭后也继续。新加入的主机会被发现，明确暂停的主机保持暂停。

后台恢复只读 `thread/loaded/list`、会话元数据和轮次摘要，不自动恢复会话写入者、不调用 `turn/start`。已观察运行的任务记录保存在私有 `DATA_DIR/push-observers.json`，包含主机、会话、轮次和时间，不保存正文。重连或服务重启后核对这些任务，补齐确实错过的完成事件；不会把所有旧历史当作刚完成的任务重发。正常投递仍使用现有的授权、偏好、去重、持久 outbox 和重试机制。

“设置 → 应用与通知”显示后台观察状态，可区分等待连接、观察中、自动重连、主动暂停及观察日志存储失败。没有有效通知授权时不会为推送主动保持主机连接。对 Web 从未观察到的任务、Web 服务停止期间开始并结束的外部任务，无法保证事后恢复通知。

Android 的网络、浏览器后台限制和系统省电仍可能影响送达。排查时先看后台观察是否连接、服务端投递是否已接受，再检查手机设备授权和系统状态；不要用本地系统通知测试来证明远程推送链路正常。
